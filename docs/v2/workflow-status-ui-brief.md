# 当前会话的工作流状态

用户诉求：dsh 会话里能持续看见工作流走到哪一步、失败预算用了多少、当前在执行、验证、暂停还是等待人工放行。机制取证见 [workflow-status-ui-research.md](workflow-status-ui-research.md)。

## 目标与边界

在当前 Chat 提供可折叠状态卡与页头入口。摘要展示工作流、当前步、本步失败预算及本轮验证进度；展开查看步骤、本轮各票与报告。遇到分支、循环与回退不编造完成百分比，不把失败预算称作整个运行的累计失败次数。

引擎仍是唯一事实源与推进者。不改变判定、验证者、投递分类、reset 时序或模型上下文；状态查询与展开不追加会话消息、不唤醒模型、不新增 SessionEvent、不落盘派生相位。使用 dsh 公共扩展能力，不改宿主、不加插件轮询或定时器。新增只读状态流独立于原有生命周期播报。

## 完成判据

1. **真机看见**：真实 dsh 的 Chat 中显示卡片，长对话滚动仍能看见；折叠可用；原生审批接管时页头仍能打开详情。无工作流的会话不出现空卡。
2. **事实准确**：执行、逐票验证、失败返工、暂停、人工审查及完成/取消与真实引擎一致。多张失败票只计一轮失败；infra 不计失败预算且保留已通过票。写盘失败显示最后确认值并提示故障；归档失败不伪装成已完成。
3. **恢复与隔离**：刷新、reset、断线期间事实改变后重连、宿主重启均可恢复。断线明确标记旧值；只显示当前会话拥有的实例。接管清除旧属主卡片，fork 不继承父会话的活跃或终态卡；完成/取消只关联本会话自己的精确报告。
4. **负对照不能省**：同一真实运行、同一 DOM 断言，移除状态客户端后失败，恢复后通过。另保留 opening snapshot、阻断变化通知，真实票已落账但实时 DOM 断言必须失败；恢复推送后通过。
5. **行为隔离**：查看/展开不写会话事件、不额外开回合；页头与卡片共享一条按会话绑定的流；最后订阅释放、关闭页面及插件卸载终止监听，迟到值不能覆盖新绑定。原有全量回归保持通过。

## 验证入口

- `npm run build && npm run typecheck && npm run verify`：内核、契约、生命周期、发布装配与既有回归。
- `node scripts/ui-status-web.mjs`：隔离 HOME/工作区的真实 dsh web、真实 AgentLoop/原生验证者/Chat DOM。模型输出由本地夹具控制，不消耗远程模型额度。
- 验收记录：[evidence/ui-status.md](evidence/ui-status.md)。运行中的用户宿主需要重启才能载入新的宿主模块；浏览器需刷新载入新客户端。
