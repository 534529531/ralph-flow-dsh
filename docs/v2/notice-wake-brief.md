# 播报不该唤醒会话（缺陷修复）

## 问题

`loop` 的对抗验证跑在独立会话里：四张票并行、全过才放行，最后一票落地后由**程序**聚合判定、决定返工或推进。这条链路本身是对的（引擎 `await Promise.all(N 票)`，只有摘掉最后一笔委派的那一次触发聚合）。

缺陷在**播报**上：引擎的播报与指令共用同一个出口，都走 `agent.steer`；而 dsh 的 `steer` 在**空闲**驱动器上会**开一个新回合**（`dsh-agent` 文档原话 *An idle driver starts a turn*；`dsh-agent-loop` 实现 `steer → send(msg, 'next-step', true)`）。于是「给人看的进度播报」把模型叫醒了。

作者实测（`/home/yj/ra2-engine-rebuild` 的真实 `loop`，实例 `loop-mutr5mu8-fw8d`，四票里两票判失败）：

| 时刻 | 事实 |
|---|---|
| 20:30:10 | 执行者交卷，回合结束 |
| 20:34:23.883 | 第一张票的播报投出 → **开了新回合**；243 ms 后落成一条 user/message，全文只有一行「🔍 ❌ 验证者 2/4 不通过：实现的行为符合预期，真实可用」 |
| 20:34–20:48 | 执行者手里**没有 DO**，自己开工（`ralphflow_status` + 一连串 bash） |
| 20:40:00 | 四票齐 → 判失败 → 引擎要「替换上下文 + 带失败理由重投 DO」→ 卡在 `await agent.whenIdle()`（上面那个无人指挥的回合不收工） |
| 20:48:14 | 执行者**自己**调 `ralphflow_submit`（它从回合 1 残留的上下文里知道这个协议）→ 被当成第 2 轮交卷 → 又发 4 张票 |
| 20:51:38 | 回合终于结束 → 空闲窗口拿到 → 但 `do_submitted` 已是 true → 守卫判 `instance_gone` → **重置与返工 DO 一起被丢弃** |

三个连带后果都真实发生过：① 验证期间无 DO 自行开工；② `ralphflow_submit` 之后那条「已交卷」播报把**本已收尾的回合续上**，模型在验证者取证期间继续改工作区（判定对象在动）；③ 返工的重置与 DO 投不出去。

**取证路径**（自行复核，不采信上面这段自述）：

- `.dsh/ralph-flow/instances/loop-mutr5mu8-fw8d/execution.log`：`reset_do_dropped reason=instance_gone`、两次 `do_submitted`、两次 `verify_start`
- `~/.dsh/sessions/--home-yj-ra2-engine-rebuild--/session-b4483cb9-f25b-43d7-a652-330471f70de7/session.v4.jsonl.zstd`：`turn/start turn=2` 与紧随其后的播报 user/message；`surfaceOp:{op:"replace"}` 事件数 = **0**（上下文从头到尾没被替换过）

**宿主事实**：dsh 有**不唤醒**的投递路径 —— `inject(msg)`，以及 `send(msg, target, wakeup=false)`（`dsh-agent-loop` 里 `inject → send(msg, 'next-step', false)`）。dsh 自己的 `dsh-tool-jobs` 播报后台任务完成时用的就是 `inject`。

## 目标

把投递分成两类，各自走对的路：

- **播报**（给人看的记录）：落到会话里、用户在时间线上**立刻**看得见，且**模型不被唤醒** —— 空闲会话保持空闲，正在收尾的回合不被续上。
- **指令**（要模型干活）：照旧唤醒驱动器 —— 下一步的 DO 提示词、命令要模型转达的话、turn-stopping 里「你还没交卷」的提醒。

于是这条链路真正跑通：验证者全部跑完 → **程序**判失败 → **程序**替换上下文 + 用 DO 唤醒模型（带全部失败理由）→ 模型在干净上下文里返工。

播报仍属于会话（模型在下一回合能看到它），且必须仍被 reset 整段遮蔽：替换完成后，模型上下文仍精确等于「系统提示 + 交接稿 + 本步 DO」。

## 边界

- 推进权仍在程序手里：判定聚合、返工/推进、重置时序、fail-closed 计票都不动。
- 判定权仍在独立会话：验证者 prompt 仍不含执行者自述。
- 不给模型任何新的可调用修复入口。
- 只用 dsh 的公开 API，不改 dsh 本体；不为更老的 dsh 留兼容分支。
- 「全过才放行」不弱化：不要为了让返工早点开始而提前收票或提前结算。

## 完成判据

1. **每一处投递都归类过**：全仓所有把消息投进会话的调用点，逐条判定「指令」还是「播报」，代码里看得出这个判定。漏一处即未完成。
2. **播报不唤醒**：空闲会话上投播报后驱动器仍空闲；回合正在收尾时投播报不把回合续上。
3. **播报立刻可见**：空闲时投出后**立刻**出现在会话里（用户时间线上马上多一行），不是等到下一回合才出现。
4. **指令仍唤醒**：下一步 DO、命令指令、交卷提醒仍走唤醒路径。
5. **重置遮蔽不变**：替换完成后表面 = 系统提示 + 交接稿 + DO，播报不在其中。
6. **原有功能不退化**：`npm run build && npm run typecheck && npm run verify` 全绿。测试跟着功能改，不许为了让测试过而妥协功能。
7. **真实运行复核**：在一个真实 `loop` 实例里观察到 —— 验证期间该会话**没有**新回合；四票齐后会话里出现 replace 事件（上下文确实被替换）且 DO 送达。短任务即可，不必复现 RA2 那种规模。
